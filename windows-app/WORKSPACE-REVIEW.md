# Monitoring workspace — 0.15.2

The user's priority is a single visible monitoring screen with stronger hierarchy and responsive behavior. The model is explicitly excluded from that screen and moved to its own lazily loaded 3D tab. No reference asset or original model project is deleted.

The layout reserves remaining viewport height for three equal graph rows. Each retains its own left-hand axis values, sample time and raw/formula menu. Temperature, frequency and connection/acquisition metadata form a compact context rail; on portrait tablets they move above the full-width plots. The duplicate channel table and nameplate are available in a floating panel. A context toggle gives the plots more width; actual one/five/thirty-minute shortcuts change the plotted window. Below 1180 px the registry is an overlay drawer. The Windows app starts within the primary display's work area and supports a 768 px minimum width.

The white/violet monitoring surface extends across the registry and graph workspace. Hover or keyboard focus on an axis emphasizes the corresponding traces across all graphs without removing other measurements. Keyboard focus takes priority. Linked time cursors and chart pause remain; redundant pause toasts are removed because they obscured lower plots. Reduced motion is respected.

Manual raw/formula popovers use the native top layer, preventing clipping by bounded graph panels. Pinning retains the displayed timestamp. Escape/outside interaction, switching tabs, hiding context and fullscreen changes close them; Escape from the isolated model frame follows the same rule. Model controls fit their separate page and fullscreen view.

Validation checks all three SVGs/readout boxes and numerical frequency inside an unscrolled main viewport at 960×680, 1366×700, 1366×768, 1280×650, 1920×1080, 1024×768 and 768×1024. The 1366×700 and 1280×650 cases model the renderer area left on common Windows displays after the title bar and taskbar use space. It also checks registry opening/closing, axis focus, quick ranges, context toggle, raw/table popovers, standalone model lazy loading and existing acquisition/recording/CRUD/history workflows. Rendered captures inspect regular desktop and short laptop viewports as well as portrait tablet composition. The Impeccable scan's under-11px functional warnings were fixed; remaining 11px auxiliary-text and child-padded legacy wrapper advisories are assessed with the screenshots, not presented as accessibility certification.

The multi-motor overview and historical tables can still scroll for larger data sets. The one-viewport guarantee applies to the selected motor monitor at the tested sizes. This release does not verify physical frequency order, internal sensor refresh timing, RMS/Peak semantics or ISO severity.

The app opens directly on the selected motor detail page. If there are no profiles yet, the same page presents the setup state; it never invents demo readings. On the history page, the previously recorded range chart is placed above the record table, defaults to the current motor when one is selected, and can switch between synchronized 2D time plots and an interactive 3D surface. The 3D surface uses timestamp × X/Y/Z axis × the selected saved scalar measurement (velocity, displacement, acceleration or confirmed frequency). Drag rotates, wheel zooms, and keyboard arrows rotate. Missing channel values remain gaps; the plot is not an FFT or frequency spectrum because the sensor records aggregate channel values rather than waveform samples or frequency bins. Changing the motor or range clears the chart until the new saved range is loaded. Tests cover filtering to a specific motor, value families, chart clearing and overflow at desktop/tablet widths.

The detector also flags the legacy base dialog shadow in styles.css while evaluating a page with a dark registry. The active theme overrides that base shadow; the rendered dialogs remain white with an offset shadow. The table/dialog wrappers delegate inset spacing to their cells and child sections. These legacy findings do not justify adding duplicate padding or replacing the established form layout.

Saved history now filters the current sensor identity in the data store before reducing points, preserving the correct count and compatible extrema. Legacy custom values without their original decoder remain available through explicit history rather than automatic restoration. Original acquisition gaps and null-channel boundaries survive reduction and are carried into monitor, overview and historical plots. Reduced points no longer create artificial outages. Restored data is labelled as history without claiming that an older file has a matching CSV export.

The history motor selector includes recorded IDs outside the active registry. An ID that was removed or renamed remains available for historical charts. Different units, custom register/formula configurations and sensor sources are separate recorded series; the newest series is selected initially and other series can be chosen without mixing their scales. Programmatic motor changes invalidate prior curves and raw snapshots.

The historical 3D view now projects actual timestamps, preserves extrema rather than uniformly dropping samples, keeps isolated points visible and breaks paths at missing values. Picking uses projected coordinates after rotation, and Hz requires a confirmed recorded status. Keyboard time/axis selection, tap selection, zoom, reset and fullscreen share the same saved readings. Pure data tests cover these invariants; the separate history UI test launches with existing saved profiles and verifies archive selection, schema changes, continuity, keyboard controls and fullscreen/Escape.
